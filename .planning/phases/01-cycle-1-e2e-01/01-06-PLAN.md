`p0_records` constraints and indexes:

- unique `(record_code, logical_identity)`;
- exact closed CHECK for all 17 `P0RecordCode` values and all 17 registry `(record_code, record_schema_version)` pairs;
- `logical_identity` must be a JSON array and `envelope` a JSON object;
- `state_version IS NULL OR state_version >= 1`;
- `attempt_count IS NULL OR attempt_count >= 0`;
- indexes on `(scope_owner_customer_id, record_code)`, `(record_code, run_id, lifecycle_status)`, `(record_code, task_id, lifecycle_status)`, `(record_code, request_unit_id)`;
- stable partial recovery-candidate index on active `agent_run` rows using `(recovery_sort_at, record_id)`;
- physical query projections are derived from and exactly cross-checked against strict decoded records; they never replace codec truth or grant authority.

`p0_record_references` constraints and indexes:

- source and target composite FKs reference `p0_records(record_code, logical_identity)`;
- both FKs are transaction-safe `DEFERRABLE INITIALLY DEFERRED`;
- source delete may cascade; target delete is restricted;
- unique `(source_record_code, source_logical_identity, ordinal)`;
- unique `(source_record_code, source_logical_identity, relation, target_record_code, target_logical_identity)`;
- explicit target-side index `(target_record_code, target_logical_identity)`;
- envelope and its complete normalized reference set are written and validated in the same transaction.

Record write semantics:

```text
same logical identity + same exact envelope/reference set
  -> existing idempotent replay result

same logical identity + different envelope/reference set
  -> bounded P0PersistenceIntegrityError

conditional aggregate command
  -> lock in stable (record_code, canonical logical identity) order
  -> compare exact expected state/version/projection
  -> require exact affected-row counts
  -> persist every next record/reference or roll back all
```

Tool dispatch semantics:

```text
READ CREATED ToolCall
  -> atomically CAS ToolCall to RUNNING and persist first unfinished attempt
  -> return APPLIED only after commit
  -> external order read may happen only after APPLIED

ACTION ToolCall
  -> ACTION_LEDGER_REQUIRED
  -> zero ToolCall/attempt/reference writes
```

Recovery semantics:

```text
load_next_restart_recovery_closure
  -> one REPEATABLE READ snapshot
  -> deterministic active-run ordering
  -> SQL LIMIT 2 before materializing each max-one relation family
  -> jsonb child-count preflight before decoding TaskStateTransition/ToolAttempt tuples
  -> strict record/ref/owner decode
  -> deterministic closure fence over stable exact envelope/reference bytes

claim_and_apply_restart_recovery
  -> one SERIALIZABLE transaction
  -> stable lock order and exact closure/fence re-read
  -> closure drift or serialization failure: CLOSURE_CONFLICT and rollback
  -> RUNNING Action: RECONCILIATION_REQUIRED and zero state/Trace writes
  -> APPLIED: Run/Task/RequestUnit/ToolCall/link projections plus supplied 1-3 canonical TraceEvents in one commit
  -> any row-count, FK, Trace or integrity failure: total rollback
```

Owner-scoped order query:

```sql
SELECT order_payload
FROM mock_orders
WHERE customer_id = :trusted_customer_id
  AND order_id = :candidate_order_id
```

There is no order-id-only fetch followed by an owner check. No row and foreign-owned row both map to the existing `NOT_FOUND_OR_NOT_ACCESSIBLE` result with no payload. A database/system failure maps to the existing bounded system-failure result and never includes the raw exception.
