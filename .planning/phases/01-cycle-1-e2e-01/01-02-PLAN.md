<threat_model>

Trust boundaries:

- authenticated Application context → owner-scoped persistence read: trusted identity remains server-derived and is never reconstructed from stored payload;
- physical row / metadata → semantic owner model: record identity and logical version are validated before payload interpretation;
- startup recovery authority → active Run / Task / ToolCall records: internal authority permits discovery/claim but cannot make an invalid record trustworthy;
- semantic owner migration approval → Infrastructure migration mechanics: physical access does not authorize implicit logical conversion;
- internal integrity diagnostics → ordinary Trace / HTTP / model context: diagnostics remain restricted and cannot disclose row existence, raw payload or unnecessary PII.

STRIDE register:
