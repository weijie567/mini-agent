## Scoped encoding decisions

- Phase 1 v1 Tool DTO 与 Gateway 函数保持原名、原字段和现行语义；Cycle 2 使用显式
  `V2` / `cycle2` 命名的 inactive additive surface，避免在 02-06 codec/cutover 前让
  v1 serialization 产生隐式字段漂移。
- `search_orders_tool_spec()` / `get_shipment_tool_spec()` 只编码 agent-visible schema；
  Runtime-private outcome、business DTO、source authority 继续由 02-01 及 scoped Spec
  拥有，不在 `tool_system.py` 重建。
- 三工具 snapshot 可以由 pure builder/validator 形成，但 handler ref 只是 Core
  registration identity，不证明 Adapter、composition 或 dispatch 已实现。
- Cycle 2 Gateway helper 消费显式 current accepted binding closure；它不解析自然语言、
  不创建 InputBinding、不解析“第二个”，也不解析 CandidateSet target。02-08 才拥有
  RU / binding reducer，02-10/02-11 才拥有 Runtime orchestration。当前
  `RevalidatedNextMove` 仍是 Phase 1 `order_id`-only surface；02-04 可以新增 Tool-owned
  typed candidate / binding facts DTO，但不得以 caller-supplied boolean、public summary、
  ordinal 或模型 target 冒充 provenance 或 end-to-end authorization。
- `get_order` 与 `get_shipment` 的 authority 不合并：`get_order` 保留 Phase 1 当前
  accepted `order_id InputBinding` 路径，以 owner-scoped read 验证订单；只有
  `get_shipment` 要求已由确定性 closure 形成的 current verified order target。任何
  helper 都不得把 USER_CLAIM binding 本身升级为 verified fact。
- Recovery contract 只表达 safe decision 与 closed matrix；durable CAS、append attempt
  fence、codec 与 executor 分别属于 02-05/06/09，不能由 pure helper 冒充已实现。
- shared `TraceEvent` structure 不变；02-04 不修改 `trace.py`。
